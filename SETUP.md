# MedReady — Project Setup (clasp / GitHub / Google Sheets)

This is the one-time environment setup to do **before** Antigravity (or you)
starts writing code. It gets you: a local project synced to Apps Script via
`clasp`, that project tracked in a GitHub repo, and a Google Sheet wired up
as the database.

---

## 1. Prerequisites

- Node.js installed (for `npm`/`clasp`)
- A Google account with access to Google Apps Script and Google Sheets
- A GitHub account (for version control / CI, optional but recommended)
- Git installed locally

---

## 2. Install and authenticate clasp

```bash
npm install -g @google/clasp
clasp login
```

This opens a browser window to authorize clasp against your Google
account and stores credentials locally (`~/.clasprc.json` — never commit
this file).

Then enable the Apps Script API for your account (one-time, per Google
account): visit https://script.google.com/home/usersettings and turn
**Google Apps Script API** ON. `clasp push`/`clasp create` will fail with a
403 until this is on.

---

## 3. Create the Apps Script project

### Option A — brand new project (no Sheet yet)

```bash
mkdir medready && cd medready
clasp create --title "MedReady" --type standalone
```

You'll bind it to a specific Sheet later via `SpreadsheetApp.openById()` in
code (recommended — keeps the script deployable/testable independent of
any one Sheet).

### Option B — container-bound to an existing Sheet

1. Create the Google Sheet first (see §5).
2. In the Sheet: **Extensions → Apps Script** to create the bound script.
3. Locally: `clasp clone <scriptId>` (get `scriptId` from
   **Project Settings** in the Apps Script editor, or from the URL).

This repo uses **Option A (standalone script)** — bind to the Sheet by ID
in code, not by container-binding — so the same script can be redeployed or
pointed at a new Sheet without recreating the whole project. Store the
Sheet ID in **Script Properties**, not hardcoded (see §6).

## 4. Project structure

```
medready/
├── .clasp.json          # local only — scriptId + rootDir (see below)
├── .claspignore          # files clasp should NOT push to Apps Script
├── .gitignore             # files git should NOT commit
├── appsscript.json        # Apps Script manifest (scopes, webapp config)
├── src/
│   ├── Code.js            # doGet(), setupSystem(), routing
│   ├── Auth.js             # allowlist check, role/ward-scope resolution
│   ├── Cases.js            # case CRUD + state machine
│   ├── Timeline.js
│   ├── Sla.js
│   ├── Notifications.js
│   ├── Admin.js
│   └── ...
└── ui/
    ├── index.html          # HtmlService entry template
    ├── ward-dashboard.html
    ├── pharmacy-dashboard.html
    ├── board.html
    ├── case-detail.html
    └── ...
```

`.clasp.json` (generated by `clasp create`/`clasp clone` — do **not** hand-edit
the `scriptId`):

```json
{
  "scriptId": "YOUR_SCRIPT_ID_HERE",
  "rootDir": "./src"
}
```

> ⚠️ HTML files served via `HtmlService.createTemplateFromFile()` also need
> to be pushed — either keep them under `rootDir` too, or add a second clasp
> project config / adjust `rootDir` to a common parent (e.g. `./` with
> `src/` and `ui/` both inside it) so `clasp push` picks up everything.

`.claspignore` (don't push local tooling to Apps Script):

```
**/**
!src/**
!ui/**
!appsscript.json
node_modules/**
.git/**
```

## 5. appsscript.json manifest (web app config)

```json
{
  "timeZone": "Asia/Bangkok",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "webapp": {
    "executeAs": "USER_DEPLOYING",
    "access": "DOMAIN"
  },
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/drive",
    "https://www.googleapis.com/auth/script.external_request",
    "https://www.googleapis.com/auth/userinfo.email"
  ]
}
```

Notes:
- `"access": "DOMAIN"` restricts the web app to your Google Workspace
  domain at the platform level — this is in *addition to*, not a
  replacement for, the app-level Gmail allowlist check in `Auth.js`.
  If MedReady's users aren't all on one Workspace domain, use
  `"MYSELF"` + a manually shared deployment list, or `"ANYONE"` and rely
  entirely on the in-app allowlist (less recommended).
- `"executeAs": "USER_DEPLOYING"` is usually right for a shared internal
  tool so all writes hit the Sheet under one service identity; if you need
  per-user Sheet permissions instead, use `"USER_ACCESSING"` — but then
  every Ward/Pharmacy user needs direct Sheet access, which usually isn't
  what you want for a pseudonymized shared operational tool.
- `userinfo.email` scope is what lets `Session.getActiveUser().getEmail()`
  reliably return the signed-in user's email for the allowlist check.

## 6. Google Sheet setup

1. Create a new Google Sheet — e.g. "MedReady Database" — in a shared
   Drive folder the pharmacy/ward team (or at least the service account)
   can access.
2. Copy its **Spreadsheet ID** from the URL:
   `https://docs.google.com/spreadsheets/d/`**`THIS_PART`**`/edit`
3. In the Apps Script project, bind the Sheet ID using one of the following methods:
   - **Method A (Easiest)**: Run `setPrimarySpreadsheetId('YOUR_SPREADSHEET_ID')` in Apps Script Editor.
   - **Method B**: Set `CONFIG.SPREADSHEET_ID = 'YOUR_SPREADSHEET_ID'` in [Config.js](file:///d:/MedReady/src/Config.js).
   - **Method C**: Project Settings → **Script Properties** → add key `SHEET_ID` with the Spreadsheet ID.
   - **Method D (Auto)**: If omitted, the system will automatically search Google Drive for an existing "MedReady Database" and bind to it rather than creating duplicate files.

4. **Cleaning up existing duplicate files in Google Drive**:
   - Run `listDuplicateDatabases()` in Apps Script Editor to view all duplicate spreadsheets.
   - Run `cleanupDuplicateDatabases(keepSpreadsheetId, trashDuplicates)`:
     - e.g., `cleanupDuplicateDatabases(null, true)` will automatically pick the best database file, bind it, and move the empty/redundant duplicates to Drive Trash.

5. Run `setupSystem()` once to verify and ensure all sheets, headers, and tabs exist idempotently.

## 7. GitHub setup

```bash
cd medready
git init
git add .
git commit -m "Initial MedReady project scaffold"
git branch -M main
git remote add origin https://github.com/<your-org-or-user>/medready.git
git push -u origin main
```

`.gitignore` (don't commit local credentials or scriptId if you want the
repo shareable/public — keep it if the repo is private and you want the
scriptId tracked):

```
node_modules/
.clasprc.json
*.log
```

> If you want the repo to work for teammates who clone it and run their own
> `clasp login`, exclude `.clasp.json` too (each dev/CI then needs their own
> `scriptId` locally or you inject it via CI secrets). If it's a single
> shared script deployment, it's simpler to commit `.clasp.json` as-is.

### Optional: GitHub Actions to auto-push to Apps Script on merge to `main`

`.github/workflows/deploy.yml`:

```yaml
name: Deploy to Apps Script

on:
  push:
    branches: [main]

jobs:
  clasp-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install -g @google/clasp
      - name: Restore clasp credentials
        run: echo '${{ secrets.CLASPRC_JSON }}' > ~/.clasprc.json
      - run: clasp push --force
```

To get `CLASPRC_JSON`: run `clasp login` locally once, then copy the full
contents of `~/.clasprc.json` into a GitHub repo secret named
`CLASPRC_JSON` (**Settings → Secrets and variables → Actions**). Treat this
value as a full credential to your Google account's Apps Script access —
store it only as a secret, never in code or commit history.

## 8. Day-to-day workflow

```bash
# pull latest from Apps Script into local files (rare — usually local is source of truth)
clasp pull

# push local changes to the Apps Script project
clasp push

# open the project in the Apps Script web editor
clasp open

# create/update a deployment (new web app version)
clasp deploy --description "v1"

# list existing deployments (to get the deployment ID / web app URL)
clasp deployments
```

Typical loop while building: edit locally → `clasp push` → test in the
Apps Script editor or the `/exec` web app URL → commit to git when a chunk
of work is done → (optional) GitHub Action deploys on merge to `main`.

## 9. Quick checklist

- [ ] `clasp login` succeeded, Apps Script API enabled
- [ ] `clasp create` (or `clasp clone`) run, `.clasp.json` has a real `scriptId`
- [ ] `appsscript.json` has correct `webapp.access` for your user population
- [ ] Google Sheet created, ID stored in Script Properties as `SHEET_ID`
- [ ] `setupSystem()` run once, all tabs/headers verified in the Sheet
- [ ] Gmail allowlist tab populated with at least your own account for testing
- [ ] Git repo initialized and pushed to GitHub
- [ ] (optional) GitHub Action + `CLASPRC_JSON` secret configured for auto-deploy
- [ ] `clasp deploy` produces a working `/exec` URL you can open and sign into
